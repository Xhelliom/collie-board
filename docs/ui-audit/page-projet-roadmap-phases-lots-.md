# Audit UI — page projet : roadmap, phases, lots, autonomie, orchestrateur (mobile 390 px)

**Méthode du rendu mobile** : lecture du code (`router.tsx` → `routes/project.tsx`, `components/project-roadmap.tsx`, `repo-flow.tsx`, `phase-template.tsx`, `project-lots.tsx`, `project-step.tsx`, `project-milestones.tsx`, `orchestrator-panel.tsx`, `autonomy-settings.tsx`, `kpi.tsx`, `board-tabs.tsx`) et des classes Tailwind, avec les libellés français de `i18n/messages/project.ts`. Un rendu réel a été **tenté puis abandonné** : l'extension Chrome est connectée, mais le navigateur ne joint ni `127.0.0.1:8788` ni l'URL tailnet, et le redimensionnement à 390 px n'a pas pris (la fenêtre est restée à 1920 px). Les points marqués *(à confirmer)* sont déduits des classes et non vus à l'écran. Aucun fichier du code modifié.

Audit voisin : [panes, spaces, galerie, réglages](./panes-spaces-galerie-reglages.md) (son point #4 sur l'autonomie rejoint le #12 ci-dessous).

## Ordre actuel des blocs (mobile, de haut en bas)
En-tête (dépôt + bouton « Orchestrateur ») → onglets + sélecteur de dépôt (2 rangées) → résumé en prose → anneau 144 px → 4 KPI → bandeau « étapes hors phase » → flow par défaut du dépôt → roadmap (repliée) → **« À toi »** → cartes de phases (défilement horizontal) → barre de filtres collante → sections de phase (modèle + flow, lots, étapes) → phases validées.

## Ce qui est bien
La roadmap est repliée par défaut avec un raccourci « Aller à <phase active> ». Les phases validées sont repliées en fin de page. La barre de filtres est collante et le filtre est mémorisé. Le chat de l'orchestrateur est dans une feuille de hauteur fixe sur mobile (le champ reste visible) et se recharge sur le cycle de la racine. Les feuilles de confirmation (valider une phase, lancer un lot, jalonner) ont des champs en `h-10`. `min-w-0`, `break-words` et `truncate` sont présents presque partout. Les animations respectent `prefers-reduced-motion`.

## Options et recommandation
- **A — ordre et densité** (#1, 3, 4, 11, 14) : surtout du déplacement et de la suppression, risque faible.
- **B — corrections mobiles** (#2, 6, 15) : petits diffs ciblés.
- **C — textes longs et doublons** (#5, 7, 8, 13) : à faire carte par carte.
- **D — refonte réglages et orchestrateur** (#9, 10, 12) : dépend des réponses Q1 et Q2.

**Recommandation** : A et B dans une même carte (même fichier, `project.tsx`), C ensuite, D après décision.
