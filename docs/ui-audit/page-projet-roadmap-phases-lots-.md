# Audit UI — page projet : roadmap, phases, lots, autonomie, orchestrateur (mobile 390 px)

**Méthode du rendu mobile** : **rendu réel** dans Chrome headless local (`google-chrome-stable --headless`), sur la page `board/project?repo=…/collie-board` du pont en service (`127.0.0.1:8788`), avec les données réelles : 15 étapes, 3 phases ouvertes, 3 phases validées.
- Deux captures, à 390×844 et à 390×4000. Comme la page défile dans son `<main>`, la seconde montre environ 4 000 px sur un total mesuré de 6 745 px.
- Mesures dans la même page avec le DevTools Protocol, viewport 390×844 en mode mobile : débordements horizontaux, taille de chaque élément cliquable, troncatures, position des blocs.
- Ce qui reste **lu dans le code** : le panneau de l'orchestrateur et l'autonomie (#12, dans une feuille non ouverte), les feuilles de confirmation, et les états vides (#13) que ces données ne produisent pas.
- #2 n'apparaît pas avec ces données. Il a été **simulé** : le texte du bouton et du titre de section a été remplacé dans le DOM de la page (pas dans le code).

L'extension Chrome, elle, ne joint pas le pont. Aucun fichier du code modifié.

Audit voisin : [panes, spaces, galerie, réglages](./panes-spaces-galerie-reglages.md) (son point #4 sur l'autonomie rejoint le #12 ci-dessous).

## Ordre actuel des blocs (mobile, de haut en bas)
En-tête (dépôt + bouton « Orchestrateur ») → onglets + sélecteur de dépôt (2 rangées) → résumé en prose → anneau 144 px → 4 KPI → bandeau « étapes hors phase » → flow par défaut du dépôt → roadmap (repliée) → **« À toi »** → cartes de phases (défilement horizontal) → barre de filtres collante → sections de phase (modèle + flow, lots, étapes) → phases validées.

## Ce qui est bien
La roadmap est repliée par défaut avec un raccourci « Aller à » vers la phase active. Les phases validées sont repliées en fin de page. La barre de filtres est collante et le filtre est mémorisé. **Mesuré** : aucun débordement horizontal de la page avec les données réelles (`scrollWidth` 390 = largeur) ; les cartes de phases et les filtres défilent dans leur propre rangée, comme prévu. Le `pb-24` du `<main>` dégage bien la fin de page de la barre de navigation (71 px). Le chat de l'orchestrateur est dans une feuille de hauteur fixe sur mobile (le champ reste visible) et se recharge sur le cycle de la racine. Les feuilles de confirmation (valider une phase, lancer un lot, jalonner) ont des champs en `h-10`. `min-w-0`, `break-words` et `truncate` sont présents presque partout. Les animations respectent `prefers-reduced-motion`.
